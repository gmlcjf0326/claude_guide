# 16 — Public-Sector Design: KRDS-Anchored, Verified, Not-AI-Looking
> 🇰🇷 공공기관 프로토타입·웹사이트의 디자인 기준서. 토큰 실물은 `templates/design/`에 있고, 여기의 모든 대비율 수치는 WCAG 공식으로 **실측 검증**된 값이다.

## 1. Why KRDS is the anchor

KRDS(대한민국 정부 디자인 시스템)는 2025년 1월 행정안전부가 정식 개시한 범정부 UI/UX 표준으로, 전자정부법 계열 지침에 근거해 공공기관이 준수해야 하는 시스템입니다. 두 가지 적용 등급이 있습니다: **표준형** — 정부상징(부·처·청) 사이트는 토큰을 그대로 사용(색 변경 불가); **확장형** — 자체 CI가 있는 기관은 규칙 안에서 색·형태 변형 가능. 클라이언트가 중앙부처면 표준형이 강제라는 것부터 확인하세요 — 그 순간 팔레트 논쟁은 끝납니다.

## 2. The magic-number law (이 가이드의 심장)

KRDS/USWDS 공통 설계: **두 색 토큰의 등급 차이가 대비율을 보장**합니다.

| 등급 차이 | 보장 대비 | 용도 |
|---|---|---|
| ≥ 40 | 3:1 | 대형 텍스트(24px+/굵은 18.66px+) · UI 컴포넌트 · 테두리 |
| ≥ 50 | **4.5:1** | **본문 텍스트 (KWCAG 2.2 AA 하한)** |
| ≥ 70 | 7:1 | AAA |
| ≥ 90 | 15:1 | KRDS 고대비 모드 본문 |

실전 사용법: 검사기를 돌리기 전에 산수로 판단합니다. `gray-5` 배경 위 텍스트가 필요하다 → 5+50=55 → `gray-60` 이상이면 통과. 우리 토큰 램프로 실측 검산 완료: gray-0/50 = 4.51:1, gray-10/60 = 5.13:1, gray-0/90 = 16.18:1 — 산술이 현실과 일치합니다.

## 4. Typography law (국문 공공 웹)

- 서체: **Pretendard GOV Variable** (KRDS 지정, I/l 판별형) → CDN v1.3.9 고정 링크는 `templates/design/index.html` 참조. 일반 프로젝트는 Pretendard Variable.
- **본문 17px** (KRDS 기준 — Pretendard가 시각적으로 작게 렌더되어 16 아닌 17) · **행간 150%** 최소 · **자간 0** (국문 인위적 자간 축소 금지 — 흔한 미신) · 웨이트는 **400/700 둘만**.
- `word-break: keep-all` + `overflow-wrap: anywhere` — 어절 단위 줄바꿈은 국문 가독성의 절반이다.
- 행폭: 국문 40~50자 (`--content-max` 1200px, 본문 컬럼 `.prose` 46rem).

## 5. Application playbook — 상황별 응용법

**중앙부처 (표준형)**: `tokens-krds.css` 그대로. 바꿀 수 있는 것: 없음(색·서체). 집중할 것: 레이아웃 위계, 콘텐츠 구조, 마이크로카피(과장어 금지 — "혁신적인/최고의" 류는 KRDS가 명시적으로 금지).

**지자체·공공기관 (확장형)**: primary 색상만 기관 CI 색으로 교체 가능 — 단 교체 절차 준수: ① 새 primary-50이 흰 배경 위 최소 3:1(버튼용), 흰 글자와 4.5:1인지 실측 ② hover/active용 60·70단계를 같은 색상(hue)에서 더 어둡게 생성 ③ 나머지(회색·시스템색·타이포·radius)는 유지. 절대 불변: 대비 하한, 포커스 링, 글자크기/고대비 토글, keep-all.

**민간인데 공공풍 신뢰감**: GOV.UK풍 대체 팔레트로 시작 — 파랑 `#1d70b8`, 진파랑 `#003078`, 오류 `#d4351c`, 초록 `#00703c`, 검정 `#0b0c0c`, 연회색 `#f3f2f1`. 철학은 동일: 좁은 기능적 팔레트, 절제, 테두리 위주.

**공공 대시보드**: 범주형 색은 Okabe-Ito 토큰(`--viz-*`)만. 색+모양+직접 라벨의 3중 인코딩이 기본 — 범례에만 의존하는 차트는 반려 대상.

## 6. Not-AI-looking, public edition (10계명 — 리뷰어가 차단)

1. 장식용 그라데이션 금지 — 깊이는 1px 테두리와 radius로 (KRDS 방식)
2. 보라/인디고 기본값 금지 — primary는 정부 파랑, **액션에만** (버튼·활성탭·포커스), 배경 도배 금지
3. 60-30-10 — 중립 60% / 보조 30% / 강조 ≤10%
4. 위계는 크기+굵기로 (1.25~1.5 배율), 색으로 만들지 않음
5. radius 언어 통일 — 컨트롤 6 / 카드 8 / 다이얼로그 12, 화면마다 다르면 위반
6. 그림자 절제 — 포커스 링과 모달만; 영역 구분은 테두리
7. 행폭 제한 — 전폭 본문 금지
8. 이모지 아이콘 금지 (lucide 등 일관 스트로크)
9. 박스 속 박스·중앙정렬 만능주의 금지 — 좌측 정렬 + 8pt 그리드
10. 과장 카피 금지 — 과업 중심의 담백한 문장 (GOV.UK "지루함이 신뢰다")

## 7. CSS architecture law (비효율 코드 차단)

파일 분리 표준: `tokens.css → base.css → components.css → utilities.css`, 전부 `@layer reset, tokens, base, components, utilities, overrides` 선언 아래 — 레이어가 특이성 전쟁과 `!important`를 구조적으로 제거합니다. **개별 태그 인라인 `style=` 금지** (캐시 불가·재사용 불가·최고 특이성·테마 불가·HTML 비대화). 정직한 예외 셋: ① JS 계산 동적값(`transform: translateX(${x}px)`) ② CSS 변수 주입만(`style={{'--i': i}}` — 실제 스타일은 시트가 소유) ③ 저작 시점에 알 수 없는 인스턴스별 런타임 값. React는 CSS Modules 또는 Tailwind v4 `@theme` 브릿지(`tailwind-theme-krds.css`) — 어느 쪽이든 토큰이 유일한 소스.

## 8. Verification workflow (출고 전)

① 매직넘버 암산 → ② 최종 쌍만 WebAIM 검사기로 재확인 → ③ 키보드만으로 전 과정 주행(포커스 링 가시성) → ④ 회색조로 스크린샷 찍어 색 없이도 상태 구분되는지 → ⑤ WA인증 범위 사업이면 KWCAG 2.2 전 항목을 CI 게이트로. 마지막 정직 사항: 토큰의 70/80/90 심층 단계는 커뮤니티 재구성 값이므로, 실서비스 확정 전 `github.com/KRDS-uiux/krds-uiux`의 tokens/ 또는 `npm i krds-uiux`로 공식 값과 대조하세요 (기본 50단계·시스템색은 공식 확증 완료).
